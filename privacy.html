Privacy policy

Application: QA Crawler · Operator: Petr Kliucharev (individual) · Last updated: 29 October 2026

This policy explains what data QA Crawler accesses, why, where it is stored, and how it can be deleted. QA Crawler is a personal, locally run application that compiles a daily digest of QA job postings from public Telegram channels and emails it to its owner.

1. Information the application accesses

1.1 Public Telegram channels

The application reads posts from public Telegram channels — the same content that is visible to anyone at https://t.me/s/<channel> without signing in. It does not access private chats, groups, contact lists, phone numbers, or any non-public Telegram data.

1.2 Google user data (Gmail)

The application requests a single OAuth scope: https://www.googleapis.com/auth/gmail.send.

  • What it allows: sending an email from the owner's account to the owner's own address.
  • What it does not allow: reading, listing, searching, modifying, or deleting messages, attachments, contacts, or labels.
  • What is actually sent: one digest email per run, containing public vacancy texts, their links, and the channels they came from.

2. How the information is used

  • Filtering public posts by keywords, excluded words, and a relevance score.
  • Composing a single HTML digest email.
  • Keeping a local record of processed post IDs so the same vacancy is not sent twice.

The information is not used for advertising, profiling, behavioural analysis, resale, or training machine-learning models.

3. Where the data is stored

All data remains on the owner's computer. There is no backend server, no cloud storage, and no third-party analytics.

  • data/gmail_token.json — OAuth refresh token issued by Google, stored locally so the application can send the digest without asking for consent every day.
  • data/vacancies.db — a local SQLite database with processed post IDs, texts, timestamps, and scores.
  • logs/ — local run logs used for troubleshooting.

4. Sharing and disclosure

No data is sold, rented, or shared with third parties. The only outbound transfers are:

  • requests to public Telegram pages to read posts;
  • a call to the Google Gmail API to send the digest to the owner.

No human other than the owner has access to the stored data.

5. Retention

Local files are kept until the owner deletes them. Individual records can be removed at any time by deleting data/vacancies.db. The OAuth token remains valid until it is deleted locally or the application's access is revoked in the Google Account.

6. Security

The OAuth token and database are stored as ordinary files on the owner's computer and are protected by the operating system's user account permissions. The token is never transmitted to any server other than Google's OAuth endpoint. The application does not run a public server and does not accept inbound connections.

7. Your choices and deletion

  • Delete the data folder to remove the token and all stored posts.
  • Revoke the application's access at myaccount.google.com/permissions.
  • Uninstall the application to stop all processing.

8. Google API Services User Data Policy

QA Crawler's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

In particular:

  • Google user data is used only to provide the digest feature described above.
  • It is not transferred to third parties, except as necessary to provide that feature, to comply with applicable law, or as part of a merger or acquisition.
  • It is not used for serving advertisements.
  • It is not used to train or improve generalized AI or machine-learning models.
  • No humans read the data, except the owner of the account.

9. AI-generated content and NCII

The application does not generate, process, or distribute AI-generated imagery of any kind, including non-consensual intimate imagery (NCII), and does not use Google APIs for such purposes. It only aggregates publicly posted job listings.

10. Children

The application is not directed to children under 13 and does not knowingly collect data from them.

11. Changes to this policy

This policy may be updated. The date at the top of the page reflects the latest revision.
